## Packaging

`make-usbroot.ps1` downloads the unlocker EFI, Windows asset tool and firmware
builder from the exact release in `sources/scripts/unlocker.lock.json`. Every downloaded
file must match its pinned SHA-256 before execution or packaging. NVIDIA firmware
is obtained/generated by that builder; blobs and downloaded tools are excluded
from Git. No sibling checkout is needed.

The bundled ReBAR binary is checked against `sources/usb/manifest.json`. The resulting
folder contains:

```text
usbroot/
  EFI/BOOT/BOOTX64.EFI    ReBAR coordinator
  EFI/BOOT/UNLOCKER.EFI   standalone nv-uefi-unlocker
  *.bin                 generated firmware assets
  Collect-Windows.ps1
  ReBAR/                ReBAR build manifest and licenses
  combined-manifest.json
```

The root BOOTX64.EFI compatibility copy also points to the ReBAR coordinator.
Repeated runs always copy the unlocker from its original dependency input, so
renaming cannot accidentally turn yesterday's ReBAR loader into UNLOCKER.EFI.
The output must be inside this repository; disk-root targets and InstallTo are
rejected. The upstream builder is called with NoInstallPrompt. Copying to USB is
manual. Keep generated logs out of Git; they may contain machine identifiers.

## Boot order

1. The ReBAR coordinator discovers the RTX 3080, upstream bridge, existing BARs,
   display and available MMIO address space, and presents its menu.
2. B starts the separate tensor unlocker. The coordinator temporarily intercepts
   StartImage calls to recognize Windows Boot Manager.
3. The unlocker finishes its work and GPU reset, then attempts to start Windows.
4. The coordinator restores the original StartImage service, rediscovers the GPU,
   reserves space, selects the GA102 override and 32 GiB BAR1, relocates BAR1/BAR3,
   and adjusts the bridge window. Framebuffer comparisons and register readbacks
   verify the transaction. GOP and PCI I/O adapters expose the new mapping.
5. Windows starts with both stages applied. The 32 GiB BAR1 is an address window;
   it does not add physical VRAM. Failure paths can skip ReBAR or stop for recovery;
   a Windows boot alone does not prove either modification succeeded.

This order matters because a GPU reset after resizing could undo the ReBAR setup.
The standalone nv-uefi-unlocker is distinct from the internal HEADLESS.EFI /
UNLOCK-HEADLESS.EFI launcher/child pair discussed in earlier experiments.

## Optional ReBAR logging

Run `make-usbroot.ps1 -Logging` to enable ReBAR text logs and ACPI/driver dumps.
Without the switch they are disabled. The package always writes
`REBAR-LOGGING.TXT`: `1` enables logging and `0` disables it. A missing file
also defaults to disabled. An explicit zero makes copying a new package over
an old debug package turn logging off; existing diagnostic files are preserved.

Both the initial and post-unlock stages read the setting. Hardware checks,
allocation verification and framebuffer validation still run with logging off.
The boot volume stays open for configuration and unlocker discovery, but no
ReBAR log file is created. Requested logging errors continue to block the
affected operation. Console menus and errors remain visible.

The pinned upstream unlocker has no file-logging disable option and is kept
unchanged: its `loader.log` is independent of this switch. Running the Windows
collector manually also still writes diagnostic results.

## Validation and logs

- The user reports the manually assembled combination working on their machine.
- When diagnosing failures, regenerate with `-Logging` and keep the two newest RH logs and the unlocker's log.
- GPU-Z / NVIDIA BAR1 reporting verifies the aperture; a tensor benchmark checks
  the unlock's performance effect separately.
- Sleep/hibernate will not work and will result in a red CPU light or yellow DRAM light until reboot

## Build the ReBAR coordinator (optional)

The supplied `sources/usb/EFI/BOOT/BOOTX64.EFI` needs no compilation. To change its source,
install Python, LLVM/Clang + lld-link (LLVM 20 works fine), and an EDK II source checkout, then run:

```powershell
.\sources\Build.ps1 -Edk2 C:\path\to\edk2 -Clang C:\path\to\clang.exe -LldLink C:\path\to\lld-link.exe
.\make-usbroot.ps1
```

The build runs the host tests and refreshes the bundled EFI and manifest. Its ZIP
is the ReBAR component alone; use **usbroot** for the complete combined package.
The Windows folder generator is the combined setup entry point; sources/build.sh only
builds the ReBAR component.

## Dependency provenance

Release downloads: https://github.com/physicsdolphin/nv-uefi-unlocker/releases/tag/v2.1.11

Pins live in `sources/scripts/unlocker.lock.json`; update them deliberately when adopting
a new upstream release. Upstream GPL licensing applies to the downloaded unlocker
and its tooling; the ReBAR code retains its MIT license and EDK II notices.
